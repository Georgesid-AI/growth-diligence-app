An unanswered turnover claim opens on a disabled "Turnover – choose", never on Revenue, and may still be saved without answering.
Slow or unclear: the brief's "metric dropdown" has no match in the deck-list edit form, whose dropdown is the claim type; read as above. Spec chat-upload.md §16 and S13 still describe the one-press Calculate and "Ready for compute".
Root cause and rule: the edit form built its draft from claim_type only, so a stored answer that lives elsewhere (the turnover choice) was invisible and the first list item showed; rule: a form field whose truth lives in another stored object is prefilled from that object, with a test that opens the form on each stored value and saves unchanged.
