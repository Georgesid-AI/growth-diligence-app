Deleted: the whole-file sheet read (one call for every sheet) and the sheet reads' share of the audit's one structure lock; the 60-second page clock that started at the queue.
Decided: the gateway reads a workbook sheet by sheet (`_read_by_sheet`, one `read_structure(_unit=True)` call per sheet that holds a figure, each with its own 40,000-token input and 16,000-token output cap) and stores the merged map as one reading, because every consumer (checks, series, cards, reviewer, second read) keys on one reading per file and the full-file payload still resolves a figure that cites another sheet; a cut reply or an over-cap sheet is lost alone and stored as `unread_sheets` [{sheet, reason}], any other failure still ends the read; a second read leaves out the sheets the first lost, a re-read asks only the sheets its items name; sheet reads got their own lock step (smaller than a queue or running decks after sheets) and the page clock starts at `on_sent`, a page whose lock never came is "not_sent" with its wait, so a page can no longer time out while queued.
Slow or unclear: the finding for item 2 is yes, page reads waited behind a running sheet read (same lock, run id plus step `structures`, held by the sheet call for up to 5 minutes, inside the page's 60 s `wait_for`); the real board pack was not run here (no client data in the repository), so the fix is shown on synthetic fixtures only; a file with several sheets now takes the sum of its sheet calls one after another, not one long call.
Root cause and rule: one lock and one clock for two kinds of call of very different length; tests/test_page_clock.py pins that a sheet read never holds the page lock and that the clock starts at the send, and tests/test_sheet_by_sheet.py pins one call per sheet, the lost-sheet record and the merge.
