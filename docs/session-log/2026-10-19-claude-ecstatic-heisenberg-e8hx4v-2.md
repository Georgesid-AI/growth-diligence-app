Decided: brackets are read for the six kinds, so "Revenue (forecast)" is a forecast row; a sum never adds a marked row, a total by word anywhere in the label or by value against two or more rows since the previous total; forecast and budget columns are never read, one column per month, and the analyst's last actual month ends the dates-down series; a file with no monthly series gets the type picker and a yearly P&L no longer clears the banner (owner decision 1, which changes the old yearly-P&L test); size is the BSON size, checked on every upload and before the model is called; cells are stored as numbers, text or datetimes; the recognition of unchanged inputs is kept in a small cache; a mixed-currency file asks for no single currency (the field stays required as before the PR).
Slow or unclear: a stand-in file for a test is not harmless: replacing the CRM workbook by a nonsense file made three tests pass for the wrong reason; a fake database applies none of MongoDB's rules, so size and value types need an explicit BSON encode in the test; the sum of a metric-labelled sheet changed to a revenue summary still adds MRR, ARR and customer rows (not asked, listed for the owner).
Root cause and the rule that prevents it next time: recognition ran in Python only on labels with brackets removed and on every column before the boundary, and no test used a synthetic sheet that put a forecast where an actual belongs; the rule is that a reading rule with an exclusion list gets one test per kind of exclusion on a sheet built to break it.
