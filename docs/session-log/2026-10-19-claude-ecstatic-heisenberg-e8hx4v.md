Deleted: every xfail marker and the frontend xfail helper; the old closed-word file-type reply as the server's way to type a file (the `file_type` v2 reply replaces it); the label lines of an ARR snapshot (they added nothing the sample does not); "Required field not mapped: currency" for a file with no currency column.
Decided: Python alone recognises, the model only proposes and Python checks each proposal (the label echo is compared once and dropped, `label_matches` is what is kept); a recognised file with no customer rows is stored as the revenue file with no column mapping and waits only for its own choices; a file the rules type gets its one recognition call after its column-mapping call, so no existing payload index moves; the whole grid of each recognised sheet is kept with the dataset (over 15 MB the upload is refused with a message, never cut) so a changed as-of month or a decision re-reads the file by the same pure function; a sheet with a dated list and a metrics block gets a `series_source` (a recognised-revenue row that the list matches within 1% wins, anything else is the analyst's choice and a finding under Worth flagging); the currency the analyst confirms becomes a constant column mapped as the currency field; contract version 5.
Slow or unclear: the spec's pure tests passed on the first run but every API test touches routing the spec only sketches (typed uploads, KPI sheets, a P&L that stays the P&L, the CRM workbook with a tracker sheet); the allowance test of the spec PR was never run and uploaded a second revenue file without replacing the first; the spec does not say what the engine does with a yearly file (it gets no monthly series and a Monthly series missing line).
Root cause and the rule that prevents it next time: the specification PR could not run its API tests against any implementation, so two of them were wrong and several existing tests pinned behaviour the spec changes; the rule for the next spec-and-tests task is to list, in the spec, the existing tests the feature will change.
Process change to propose: a spec-and-tests PR names the existing tests it expects to change and a reference implementation of its API routes is run against the new API tests before the PR is opened, even if it is thrown away.
